# DocsDiver-Crew

DocsDiver-Crew is a hierarchical multi‑agent system built on CrewAI that automates security reviews of software documentation. It preprocesses your docs into a lightweight Table of Contents (ToC), then a Supervisor agent delegates targeted analysis to specialized worker agents that look for missing constraints, permission gaps, and boundary issues.

## Key Capabilities
- **Hierarchical multi‑agent audit**: Supervisor orchestrates workers; workers analyze specific risk categories.
- **Librarian pre‑processor**: Generates `ToC.json` with summaries and tags to guide delegation.
- **Context‑aware file tools**: List, read, and search `.md` files with local context windows.
- **Deterministic QC**: Integration tests can validate detection via canary tokens.

## Architecture
High‑level flow:
1. **Librarian (`src/utils/toc_generator.py`)** scans docs and generates `ToC.json`.
2. **Supervisor** receives the ToC content directly in its task prompt (no file tools).
3. **Workers** use file tools to inspect `.md` files and return findings.
4. **Supervisor** aggregates findings into `FINAL_AUDIT_REPORT.md`.

```
Docs (.md) ──▶ Librarian ──▶ ToC.json ──▶ Supervisor (no file tools)
                                         ├─▶ Negative Constraints Agent
                                         ├─▶ Permissions Agent
                                         └─▶ Boundaries Agent
                                                      │
                                                      ▼
                                        FINAL_AUDIT_REPORT.md
```

## Getting Started
### Prerequisites
- Python 3.x
- [uv](https://docs.astral.sh/uv/) installed
- API keys:
  - `OPENROUTER_API_KEY` (Supervisor LLM)
  - `GEMINI_API_KEY` (Librarian + worker LLM)

### 1) Initialize uv (first time only)
If this is your first time setting up the project with uv, from the project root run:
```bash
uv init --bare
uv add -r requirements.txt
```
This will create a `pyproject.toml`, add everything from `requirements.txt` as dependencies, and create a managed virtual environment.

After this initial migration, you can keep `requirements.txt` for reference or remove it once you are comfortable relying solely on `pyproject.toml`.

### 2) Install/refresh dependencies
Any time you pull new changes or update dependencies, run:
```bash
uv sync
```
This will (re)create the virtual environment as needed and install all dependencies declared in `pyproject.toml`.

### 3) Configure environment variables
Create a `.env` file or export in your shell:
```bash
export OPENROUTER_API_KEY="your_openrouter_key"
export GEMINI_API_KEY="your_gemini_key"
```

### 4) Prepare documentation
Create a docs directory (default is `./docs`) with `.md` files:
```
docs/
├── auth.md
├── permissions.md
└── api_limits.md
```

### 5) Run the audit
Use uv to run the entry point within the managed environment:
```bash
uv run python src/main.py --dir ./docs
```

### Outputs
- `ToC.json` — machine‑readable summary of docs (generated by Librarian)
- `FINAL_AUDIT_REPORT.md` — human‑readable findings report

## Usage Details
### CLI
`src/main.py` accepts a `--dir` argument to point at the documentation root.
```bash
python src/main.py --dir /path/to/docs
```

### Model Configuration
Model names are configured in `config.yaml` at the project root:
```
librarian_model: "gemini/gemini-2.0-flash"
supervisor_model: "gemini/gemini-2.5-pro"
negative_constraints_model: "gemini/gemini-2.0-flash"
permissions_model: "gemini/gemini-2.0-flash"
boundaries_model: "gemini/gemini-2.0-flash"
```

Environment variables can override `config.yaml`:
- `LIBRARIAN_MODEL`
- `SUPERVISOR_MODEL`
- `NEGATIVE_CONSTRAINTS_MODEL`
- `PERMISSIONS_MODEL`
- `BOUNDARIES_MODEL`

### File Tool Constraints
The custom file tools only process **`.md` files**, and `SearchFilesTool` performs a **simple text search** (no regex) with a **3‑line before/after context window**.

### ToC Generation Notes
`toc_generator.py` truncates content to the first 4,000 characters per file to limit tokens and cost. The ToC is injected directly into the Supervisor task (no file reads by the Supervisor).

## Testing
Unit tests (fast, no LLM cost):
```bash
uv run python -m unittest tests/unit/test_tools.py
```

Integration test (runs a full audit, costs tokens):
```bash
uv run python -m unittest tests/integration/test_full_audit.py
```

## Extending the System with Additional Agents
To add a new specialized agent (e.g., “Logging/Telemetry Agent”):
1. **Define the agent** in `src/agents/agents.py` with its own role, goal, and backstory.
2. **Define a task template** in `src/agents/tasks.py` describing the analysis and output format.
3. **Wire it into the crew** in `src/main.py` by instantiating the agent and adding it to the crew’s agent list.
4. **(Optional) Add QC fixtures/tests** in `tests/fixtures` and update integration tests to validate the new checks.
