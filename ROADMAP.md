## 1. Repository Audit & Current Progress
* **Codebase Maturity:** Functional MVP approaching an early beta, not yet a dependable unattended security-review product. This audit covers local `ADK_master` at `accbe0a` on 2026-11-09, comparing source with `IMPLEMENTATION_PLAN.md`, `PROGRESS.md`, and `LOG_BOOK.md`. The original coordinator-worker pipeline exists; subsequent development has concentrated on provider compatibility, prompt management, observability, and execution reuse.
* **Key Strengths:**
  - Clear responsibility boundaries across `sdaa/src/core/`, `sdaa/src/agents/`, `sdaa/src/tools/`, `sdaa/src/utils/`, and `sdaa/src/ui/`. Google ADK supplies hierarchical delegation and deterministic sequential pre-chat orchestration; a model factory and adapters isolate Gemini/OpenRouter differences.
  - Implemented capabilities include Markdown indexing with summaries/tags, three specialist workers, report persistence, interactive review, headless execution, per-agent model selection within the selected provider, prompt-to-trace linking, and bounded key-rotation attempts.
  - Tests cover provider payloads/tool calls, rotation, reporting, orchestration, and CLI behavior. Architectural/configuration/extension guides and `requirements.lock` provide useful foundations. Progress records a previous clean-environment result of **52 passed**; this is historical evidence, not a result reproduced here.
* **Current Gaps / Bottlenecks:**
  - **Security boundary:** `sdaa/src/tools/file_ops.py` uses `abspath(...).startswith(docs_root)`, which is not filesystem containment. Synthetic temporary-file probes reproduced both sibling-prefix and symlink read escapes, plus sibling-directory listing. Existing traversal tests do not cover these cases.
  - **Operational correctness:** Missing Langfuse prompts become error-text agent instructions. ToC/artifact/report reuse depends on existence, not freshness or validity; reporting failures can become returned strings. Headless completion does not consistently validate the ToC, nonempty content, or skipped-worker placeholders. `ArtifactLoaderModel` finishes with an acknowledgement rather than the artifact body expected in worker `output_key` state.
  - **Scale and auditability:** Map Maker processes whole files serially; workers can read whole documents; synthesis combines worker text without an explicit context budget. Sessions/memory are in-process, outputs use fixed filenames, and findings are free-form Markdown: the Pydantic classes in `sdaa/src/tools/reporting.py` are not the reporting contract. There is no enforced citation provenance, semantic-quality evaluation gate, checked-in CI workflow, or container deployment definition.
  - **Validation and trajectory:** All **38 application/test Python files** passed AST syntax parsing. An isolated pytest attempt using the existing Python 3.14 virtual environment stopped with **12 collection errors** because runtime dependencies including `google.adk`, `openai`, and `openinference` were absent; no current test-pass or coverage percentage is claimed. Some tests remove `output/`, making isolated execution necessary. Remote-tracking branch `origin/ADK013-02_context-mgt-implementation-jules` already contains batching/notebook work, but it is unmerged and unvalidated here. The original plan and parts of the README lag current output/skip behavior.

## 2. Tactical Roadmap (Quick Wins)
### Tactical Feature 1: Safe, Deterministic Documentation Access
- **Goal:** Make the documented filesystem boundary enforceable before allowing broader automation.
- **Problem Solved:** A worker-supplied path can currently escape the selected corpus through sibling-prefix matches or symlinks, potentially sending unrelated local content to a model.
- **Technical Steps:**
  1. Centralize path authorization in `sdaa/src/tools/file_ops.py` using `pathlib.Path.resolve()` and `relative_to()`/`is_relative_to()`, replacing string-prefix checks in both `read_file` and `list_files`.
  2. Reject symlink entries initially and validate each discovered file, not only the requested directory. Sort returned Markdown paths for reproducible indexing. Explicitly authorize the configured ToC reference instead of redirecting arbitrary paths solely by basename.
  3. Extend `tests/test_tools.py` with temporary corpora covering sibling prefixes, relative/absolute traversal, symlink files/directories, valid nested documents, and ToC access. Use the standard library; no new service or dependency is required.
- **Effort / Impact:** Effort [1/5] | Impact [5/5] — A localized correction closes reproduced access-control defects and establishes a prerequisite for safe CI execution.

### Tactical Feature 2: Versioned Local Prompt Fallbacks
- **Goal:** Keep useful agent behavior available when Langfuse is absent or unreachable.
- **Problem Solved:** Observability can degrade gracefully, but prompt retrieval cannot: agents currently receive instructions saying a prompt could not be fetched. Mock headless tests mask this by substituting prompt objects.
- **Technical Steps:**
  1. Add reviewed local text prompts under `sdaa/config/prompts/` for the three workers, coordinator, and report synthesizer. Make corpus-only access, evidence requirements, and tool/output responsibilities explicit.
  2. Extend `sdaa/src/utils/prompt_manager.py` with a small resolution contract: configured Langfuse prompt when available, otherwise the approved local version. Return prompt source/version metadata; retain Langfuse linking only for actual remote prompt objects.
  3. Update `sdaa/src/agents/workers.py`, `sdaa/src/agents/coordinator.py`, and `sdaa/config/config.yaml` to use that resolver, validate required synthesis variables, and raise actionable startup errors if neither source is usable. Avoid silently compiling an error sentence as instructions.
  4. Add `tests/test_prompt_manager.py` and a headless test without prompt-fetch monkeypatches. Verify absent credentials, retrieval/compilation failure, literal braces, and successful remote resolution; document local mode in `README.md`.
- **Effort / Impact:** Effort [2/5] | Impact [4/5] — Reuses the current prompt abstraction and removes a hidden service dependency from onboarding and offline smoke tests.

### Tactical Feature 3: Explicit Refresh and Trustworthy Completion
- **Goal:** Let users deliberately rerun analysis and distinguish a completed audit from files merely being present.
- **Problem Solved:** Edited documentation can leave old reports silently reused; incomplete or placeholder outputs can resemble success. Replayed artifacts may reach synthesis as loader acknowledgements instead of findings.
- **Technical Steps:**
  1. Add explicit `--refresh-toc` and `--refresh-audit` controls in `main.py` and a force option in `sdaa/src/core/map_maker.py`. Reject contradictory flag combinations. Refreshing the ToC must invalidate downstream reuse; refreshing an audit must bypass worker-artifact reuse. Keep this a whole-run mechanism, not incremental indexing.
  2. Add `sdaa/src/core/output_validation.py` to validate parseable ToC structure and referenced corpus paths, nonempty worker/report files, and known skipped-worker placeholders. Validate before reuse and before headless success, including `--skip-map-maker`/`--coordinator-only`; missing worker inputs must not be manufactured into successful audits.
  3. Make Map Maker/reporting failures propagate to orchestration. Adjust `sdaa/src/utils/artifact_loader_model.py` so the final worker output preserves the full reused artifact body for synthesis, not just a status message.
  4. Extend `tests/test_main_headless.py`, `tests/test_prechat_audit.py`, and Map Maker tests with stale/rebuild scenarios, invalid/missing ToC, empty outputs, failed writes, and reused-state assertions. Move destructive output tests to `tmp_path`; reconcile README skip/output documentation.
- **Effort / Impact:** Effort [2/5] | Impact [5/5] — Bounded CLI/validation changes prevent misleading success without introducing a database or changing the findings format. Automatic freshness detection remains strategic work.

## 3. Strategic Roadmap (High Investment, High Value)
### Strategic Feature 1: Evidence-Backed Findings and Quality Evaluation
- **Goal:** Turn narrative reports into validated, traceable security-review results with a measurable quality baseline.
- **Value Proposition:** Reviewers need to distinguish a documented fact, a contradiction, an undocumented control, and a confirmed implementation vulnerability. Evidence and reproducible quality checks make reports defensible and create the stable data foundation needed for comparisons and integrations.
- **Architectural Blueprint:**
  1. Add `sdaa/src/schemas/findings.py` with versioned Pydantic contracts for findings, test cases, and evidence references: stable identity, category, severity, evidence status, source agent, document hash, line range, and supporting quotation. Represent missing evidence explicitly; absence from documentation must not be asserted as proof of an absent implementation control.
  2. Add a bounded, line-aware evidence reader alongside the existing text tool in `sdaa/src/tools/file_ops.py`. Introduce validated reporting tools in `sdaa/src/tools/reporting.py` and deterministic Markdown rendering under a new `sdaa/src/reporting/` package. Verify citations against the exact input snapshot and persist JSON alongside the existing Markdown filenames.
  3. Migrate one worker at a time through `sdaa/src/agents/workers.py` and `sdaa/src/agents/coordinator.py`; preserve legacy readers during transition and label old Markdown as unverified rather than fabricating provenance. Confirm generated tool schemas work through both provider adapters.
  4. Add `evals/` with synthetic documentation, human-authored expected facts, negative cases, and versioned response recordings. Include the existing authentication roles and paid-invoice invariant as seed facts, then add deliberate contradictions and adversarial document instructions. Run deterministic schema/citation/required-fact checks offline; fail on recording misses. Use a separate opt-in live suite to measure model quality—replaying fixtures alone does not establish live accuracy.
- **Prerequisites & Risks:** Requires tactical access controls, usable prompts, and reliable completion. Define the finding taxonomy and reviewer-approved evaluation thresholds first; require valid citations for evidence-backed claims and complete recall of a small mandatory fact set. Risks include provider schema limitations, fabricated citations, overconfident severity, and prompt injection. Treat documents as untrusted data, retain deterministic authorization, and keep agent tools read-only except for constrained report persistence.
- **Effort / Impact:** Effort [4/5] | Impact [5/5] — Changes worker/reporting contracts and introduces semantic evaluation, but directly improves trust and enables every downstream product integration.

### Strategic Feature 2: Incremental, Context-Bounded, Resumable Audits
- **Goal:** Analyze large, changing documentation sets without restarting everything or exceeding model context limits.
- **Value Proposition:** Lower repeat-run cost, predictable resource use, and restartable execution make DocsDiver useful for ongoing reviews rather than occasional small-corpus experiments.
- **Architectural Blueprint:**
  1. Extract orchestration from `main.py` into `sdaa/src/core/audit_service.py`. Add corpus snapshot/chunk indexing and a run manifest keyed by document hashes, prompt versions, model/provider configuration, and schema version. Track per-stage status and output hashes; use run-specific directories and publish a latest-successful reference only after validation.
  2. Review and selectively port the unmerged ADK013 branch's `sdaa/src/core/batch_processor.py` and notebook ideas onto the hardened current adapters. Enforce token/input budgets rather than file-count-only batches, split oversized files by headings, reserve response capacity, and checkpoint worker progress in an ADK-compatible persistent session store plus a local SQLite run ledger.
  3. Start with lexical/tag retrieval and mandatory coverage of security-relevant sections; add embeddings only if evaluation shows an actual recall benefit. Track file/chunk coverage so retrieval cannot silently omit material, and preserve evidence references through bounded reduce/synthesis stages.
  4. Recompute changed ToC entries and invalidate affected findings, then rerun cross-document reconciliation and final synthesis. Additions/deletions or global policy changes should conservatively trigger wider analysis. Resume only verified matching checkpoints; invalidate unversioned legacy caches once.
- **Prerequisites & Risks:** Depends on strategic evidence identities and quality fixtures, plus tactical refresh controls as an escape hatch. Check the locked ADK session APIs before selecting persistence. Risks include inherited branch regressions, missed cross-file contradictions, shared key-rotator concurrency, duplicate provider work, and incompatible checkpoints. Begin sequentially with explicit request/token/cost ceilings; add bounded concurrency only after isolation and rate-limit behavior are tested. Benchmark against full audits for recall, cost, and restart behavior.
- **Effort / Impact:** Effort [5/5] | Impact [5/5] — Requires orchestration/storage changes, but addresses the primary scale and reliability limitations. Existing unmerged work is an accelerator to evaluate, not something to merge blindly.

### Strategic Feature 3: Pull-Request Security Review and Findings Lifecycle
- **Goal:** Deliver security-documentation feedback where changes are reviewed, with reliable baselines and human-controlled disposition.
- **Value Proposition:** Moves DocsDiver from a manually invoked report generator into a repeatable team workflow. Showing new, resolved, and recurring findings reduces review noise and supports sustained adoption.
- **Architectural Blueprint:**
  1. Add `sdaa/src/integrations/github_review.py`, a baseline/diff module, and SARIF/JSON exporters built on validated finding identities. Compare a PR's exact input snapshot with an approved base-branch audit; classify findings as new, unchanged, resolved, suppressed, or not reevaluated. Prompt/model changes require an explicit rebaseline rather than pretending to be documentation drift.
  2. Add a GitHub Actions workflow under `.github/workflows/` for offline unit/evaluation checks and a separate authorized live-review job. Introduce `--docs-root`, `--output-dir`, and `--config` overrides through `main.py` and `sdaa/src/core/config_loader.py` instead of requiring tracked YAML edits. Use those overrides for headless execution; upload reports and emit an idempotent review summary or annotation rather than duplicate comments.
  3. Add `Dockerfile` and `compose.yaml` for a reproducible locked-dependency runner, with non-root execution, a read-only corpus snapshot, a separate writable output volume, and optional local persistence from the resumable-audit service. Keep core review usable without hosting Langfuse/LangSmith.
  4. Store human dispositions with justification, owner, and expiry in a versioned policy file. Begin advisory-only; enable blocking only for reviewer-approved, evidence-backed categories after evaluation and pilot feedback. Distinguish audit infrastructure failure from a genuine security-policy failure.
- **Prerequisites & Risks:** Requires stable evidence contracts, trustworthy headless completion, approved quality thresholds, and baseline storage. Incremental runs reduce CI cost but a full-run advisory pilot can begin earlier. Use least-privilege GitHub permissions, never expose model credentials to untrusted fork execution, and avoid privileged workflows that execute untrusted PR code. Address documentation confidentiality, raw prompt/document trace export, artifact retention, and consent for third-party model processing before rollout; minimize or redact exported content.
- **Effort / Impact:** Effort [4/5] | Impact [5/5] — Baseline management, authorization, packaging, and noise control are substantial work, but this is the clearest path to recurring team usage and market readiness.

## 4. Priority Matrix & Suggested Execution Sequence
Effort is relative engineering complexity, not an elapsed-time commitment: 1 is localized, 3 spans several components, and 5 changes core architecture. Impact 4 improves routine reliability; impact 5 means foundational security/trust or a major workflow improvement. Equal impact does not imply equal urgency.

1. **Release 0.1 — Tactical Feature 1: Safe, Deterministic Documentation Access** — Effort 1/5; impact 5/5. Highest urgency because the access defects were reproduced. Exit when ordinary corpus reads work and all sibling/symlink escape cases are rejected.
2. **Release 0.2 — Tactical Feature 2: Versioned Local Prompt Fallbacks** — Effort 2/5; impact 4/5. Remove the hidden prompt-service dependency. Exit when a fresh mock headless audit works without Langfuse or substituted prompt fixtures.
3. **Release 0.3 — Tactical Feature 3: Explicit Refresh and Trustworthy Completion** — Effort 2/5; impact 5/5. Establish dependable run semantics before automating them. Exit when invalid/reused/skipped inputs cannot silently produce success and tests leave user outputs untouched.
4. **Release 0.4 — Strategic Feature 1: Evidence-Backed Findings and Quality Evaluation** — Effort 4/5; impact 5/5. Establish the data/evaluation contract. Exit when both adapters support the schema, citations are validated, and the approved offline quality gate passes.
5. **Release 0.5 — Strategic Feature 2: Incremental, Context-Bounded, Resumable Audits** — Effort 5/5; impact 5/5. Build on stable findings and measured quality, selectively reusing ADK013 work. Exit when change/resume tests pass, budgets hold, and incremental results match full-audit required-fact recall.
6. **Release 1.0 — Strategic Feature 3: Pull-Request Security Review and Findings Lifecycle** — Effort 4/5; impact 5/5. Integrate the validated engine into team workflows. An advisory full-run pilot can follow Release 0.4; complete scalable rollout after Release 0.5. Exit when baselines, permissions, idempotent feedback, dispositions, and the container runner are verified on representative repositories.

Before using these release gates, restore a clean virtual environment from `requirements.lock` and rerun the existing suite in an isolated workspace; the current dependency-related collection failure is a validation prerequisite, not evidence that application tests fail. Update `IMPLEMENTATION_PLAN.md` and `PROGRESS.md` only when roadmap items are accepted for implementation. Defer additional compliance agents, ticket synchronization, graphical interfaces, and standalone vector infrastructure until evidence quality and dependable execution are established.
